## Highlights

**Semantic cache commands (`VCACHE.*`)** — skip search + generation when a similar question was already answered:

```
VCREATE answers DIM 1536 POLICY allkeys-lru MAX_VECTORS 100000 CACHE_THRESHOLD 0.92 CACHE_TTL 3600
VCACHE.GET answers FP32 <query-vector> [FILTER 'model == "x"']   # cached answer or nil, one round trip
VCACHE.SET answers q:1 FP32 <query-vector> TEXT "<answer>"      # default TTL = CACHE_TTL
VCACHE.STATS answers                                            # hits, misses, hit_rate, avg_hit_score
VCACHE.INVALIDATE answers FILTER 'model == "x"'
```

**Prebuilt binaries** for macOS (arm64, amd64), Linux (amd64, arm64) and Windows (amd64). One file, nothing else to install:

```
curl -L https://github.com/tranbaohieu/lawliet/releases/latest/download/lawliet_darwin_arm64.tar.gz | tar xz
./lawliet_darwin_arm64/lawliet
```

## Changes since v0.1.0

- `VCACHE.GET` / `VCACHE.SET` / `VCACHE.STATS` / `VCACHE.INVALIDATE`
- Collection cache defaults `CACHE_THRESHOLD`, `CACHE_TTL` (`VCREATE`, `VCONFIG`, `VINFO`)
- Only cache hits count as accesses for LRU eviction
- RAG example uses `VCACHE`
- Release workflow publishing binaries and checksums
- Docs: positioning (semantic cache + vector store for LLM apps) and Phase 2 roadmap

## Compatibility

- Snapshot format is now version 2. v0.2.0 reads v0.1.0 snapshots; **v0.1.0 cannot read snapshots written by v0.2.0**.
- `VINFO` and `VCONFIG GET` replies have two more fields (`cache_threshold`, `cache_ttl`).

## Known limitations

Exact (flat) search only; `--maxmemory` limits estimated record size, not process memory ([TD-1](https://github.com/tranbaohieu/lawliet/blob/main/TECH_DEBT.md)). See README → Limitations.
